# PID Viewer 串口帧技术文档

> 协议文档版本：1.1  
> 适用方向：上位机与下位机固件共同实现  
> 本协议本身不携带版本字段；任何不兼容修改必须分配新的帧类型，不能直接改变既有帧长度或字段含义。

本文中的“必须”表示协议强制要求，“建议”表示推荐实现。所有偏移均从完整帧的第一个字节开始，且从 `0` 计数。

## 1. 概念

### 1.1 PID 实例

下位机维护一个或多个 PID 实例。每个实例包含：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `Pid_Id` | `uint8` | 唯一编号，从 `0` 开始连续编号 |
| `Name` | `char[32]` | PID 名称，UTF-8 编码，末尾以 `0` 填充 |
| `Kp` | `float32` | 比例参数 |
| `Ki` | `float32` | 积分参数 |
| `Kd` | `float32` | 微分参数 |
| `ref` | `float32` | 当前目标值 |
| `measure` | `float32` | 当前测量反馈值 |

上位机从 `Pid_Id = 0` 开始逐个读取 PID 实例。下位机返回“不存在”后，上位机认为已经遍历完所有实例。

`PID_INFO` 只返回名称与 `Kp、Ki、Kd`；实时的 `ref、measure` 通过 `MONITOR` 帧获得。

### 1.2 监视通道

上位机最多同时监视 4 个通道。每个通道绑定一个 PID 实例，通道编号为 `0~3`，PID 编号使用 `uint8` 表示。

未使用的通道使用 `0xFF` 作为 PID 编号。

同一个有效 PID 不应重复绑定到多个通道。下位机收到重复的非 `0xFF` PID 编号时，应拒绝整个配置并返回 `INVALID_CHANNEL`。

## 2. 串口参数

```text
波特率：115200 bps
数据位：8
校验位：无
停止位：1
流控：无
```

所有多字节整数和浮点数均使用 Little-Endian 编码。浮点数使用 IEEE 754 binary32，即 `float32`。

### 2.1 基础编码要求

- 下位机必须确认 `sizeof(float) == 4`，并按 IEEE 754 binary32 的原始位模式序列化。
- 不允许直接发送 C/C++ 结构体；字段必须逐个写入字节缓冲区。
- 读写浮点位模式时建议使用 `memcpy`，避免未对齐访问和严格别名问题。
- 发送端必须将所有保留字段写为 `0`；接收端当前应忽略保留字段的值。
- `SET_PID` 中的 `NaN` 和正负无穷必须视为非法参数。

## 3. 通用帧格式

协议不使用长度字段、序号字段或版本字段。每种帧类型具有固定长度，接收端根据帧类型确定当前帧长度。

```text
┌────────┬────────────┬──────────────────┬───────┐
│ SOF    │ Type       │ Payload          │ CRC16 │
│ 1 byte │ 1 byte     │ 固定长度         │ 2 byte│
└────────┴────────────┴──────────────────┴───────┘
```

### 3.1 帧头

```text
[0] = 0xA5
[1] = Frame_Type ^ 0x5A
```

`[1]` 解码后得到帧类型：

```text
Frame_Type = [1] ^ 0x5A
```

`Frame_Type` 不单独占用一个字节，使用 `[1]` 中的编码值表示。这样既保留帧类型信息，也可以通过 `0xA5` 搜索帧起点。

### 3.2 CRC16

- CRC 计算范围为 `[1]` 至 Payload 最后一个字节。
- 不包含帧头 `[0] = 0xA5`。
- CRC 算法采用 `CRC-16/CCITT-FALSE`。
- 多项式：`0x1021`。
- 初值：`0xFFFF`。
- 结果以 Little-Endian 发送，低字节在前。

参考实现：

```c
uint16_t pid_crc16_ccitt_false(const uint8_t *data, size_t length)
{
    uint16_t crc = 0xFFFF;

    for (size_t i = 0; i < length; ++i) {
        crc ^= (uint16_t)data[i] << 8;
        for (uint8_t bit = 0; bit < 8; ++bit) {
            crc = (crc & 0x8000U)
                ? (uint16_t)((crc << 1) ^ 0x1021U)
                : (uint16_t)(crc << 1);
        }
    }

    return crc;
}
```

标准校验向量：ASCII 字节串 `123456789` 的计算结果必须为 `0x29B1`。

### 3.3 接收状态机

1. 持续搜索字节 `0xA5`。
2. 接收下一个字节并解码 `Frame_Type`。
3. 根据帧类型查表得到固定帧长度。
4. 接收剩余字节。
5. CRC 正确则提交该帧；CRC 错误则丢弃该帧。
6. 发生未知类型、超时或 CRC 错误时，重新搜索下一个 `0xA5`。

由于帧长度固定，协议不需要转义 Payload 中出现的 `0xA5`。发送端应连续发送完整帧，不插入额外字节。

下位机建议设置约 `20 ms` 的帧内接收超时。超时后清空当前候选帧并重新搜索 `0xA5`。该值是实现建议，不属于线上的编码字段。

CRC 错误帧和未知类型帧必须静默丢弃，不能回复 ACK：此时帧类型或 Payload 本身可能已经损坏，回复可能造成错误关联。`ACK.CRC_ERROR` 与 `ACK.UNSUPPORTED_COMMAND` 保留给未来可明确识别的诊断场景，当前协议正常流程不发送这两个状态。

下位机的 ACK、PID_INFO 和周期 MONITOR 必须通过同一个发送队列串行输出，禁止不同帧的字节在 UART 上交错。

## 4. 帧类型总览

协议包含三类业务请求，每类请求对应一种下位机响应帧。

| 方向 | 类型值 | 线上 Type 字节 `[1]` | 名称 | 总长度 | 说明 |
| --- | ---: | ---: | --- | ---: | --- |
| 上位机 -> 下位机 | `0x01` | `0x5B` | `READ_PID` | 5 | 读取一个 PID 实例信息 |
| 下位机 -> 上位机 | `0x81` | `0xDB` | `PID_INFO` | 52 | 返回 PID 实例信息 |
| 上位机 -> 下位机 | `0x02` | `0x58` | `SELECT_CHANNELS` | 8 | 设置 4 个监视通道 |
| 下位机 -> 上位机 | `0x82` | `0xD8` | `MONITOR_OUTPUT` | 44 | 1.0 版 `ref/out` 监视数据，已停用 |
| 下位机 -> 上位机 | `0x84` | `0xDE` | `MONITOR` | 44 | 1.1 版 `ref/measure` 高频监视数据 |
| 上位机 -> 下位机 | `0x03` | `0x59` | `SET_PID` | 17 | 临时修改 PID 参数 |
| 下位机 -> 上位机 | `0x83` | `0xD9` | `ACK` | 21 | 返回操作结果 |

总长度包含 `SOF`、Type、Payload 和 CRC16。

## 5. 上位机发送帧

### 5.1 读取 PID 实例帧：`READ_PID`

用途：请求下位机返回指定编号的 PID 实例信息。

```text
帧类型：0x01
Payload 长度：1 byte
总长度：5 bytes
```

| 偏移 | 字段 | 类型 | 说明 |
| ---: | --- | --- | --- |
| `0` | SOF | `uint8` | `0xA5` |
| `1` | Type | `uint8` | `0x01 ^ 0x5A` |
| `2` | `Pid_Id` | `uint8` | 要读取的 PID 编号 |
| `3~4` | CRC16 | `uint16` | CRC 校验值 |

上位机从 `Pid_Id = 0` 开始递增读取。下位机返回 `PID_INFO`，当编号不存在时，`PID_INFO.Status` 返回 `NOT_FOUND`。

下位机必须在 `PID_INFO.Pid_Id` 中原样返回请求的编号，以便上位机将响应与请求匹配。当前上位机同一时间只发送一个需要应答的请求。

### 5.2 选择监视通道帧：`SELECT_CHANNELS`

用途：设置上位机需要监视的 4 个 PID 实例。设置成功后，下位机开始发送 `MONITOR` 帧。

```text
帧类型：0x02
Payload 长度：4 bytes
总长度：8 bytes
```

| 偏移 | 字段 | 类型 | 说明 |
| ---: | --- | --- | --- |
| `0` | SOF | `uint8` | `0xA5` |
| `1` | Type | `uint8` | `0x02 ^ 0x5A` |
| `2` | `Channel_0_Pid_Id` | `uint8` | 通道 0 对应的 PID 编号 |
| `3` | `Channel_1_Pid_Id` | `uint8` | 通道 1 对应的 PID 编号 |
| `4` | `Channel_2_Pid_Id` | `uint8` | 通道 2 对应的 PID 编号 |
| `5` | `Channel_3_Pid_Id` | `uint8` | 通道 3 对应的 PID 编号 |
| `6~7` | CRC16 | `uint16` | CRC 校验值 |

未使用的通道填入 `0xFF`。下位机必须先校验全部 4 个字段，再原子替换当前配置：

- 任意非 `0xFF` 的 PID 编号不存在：拒绝整个配置，返回 `PID_NOT_FOUND`。
- 同一非 `0xFF` PID 编号出现多次：拒绝整个配置，返回 `INVALID_CHANNEL`。
- 校验成功：先发送 `ACK(OK)`，从下一帧 MONITOR 开始使用新配置。
- 4 个通道全部为 `0xFF`：返回 `ACK(OK)` 并停止周期 MONITOR 发送。

配置失败时必须保留之前已生效的通道配置，不能部分更新。

### 5.3 参数调节帧：`SET_PID`

用途：临时修改一个 PID 实例的 `Kp、Ki、Kd`。参数立即生效，但不写入 Flash，设备重启后恢复原有配置。

```text
帧类型：0x03
Payload 长度：13 bytes
总长度：17 bytes
```

| 偏移 | 字段 | 类型 | 说明 |
| ---: | --- | --- | --- |
| `0` | SOF | `uint8` | `0xA5` |
| `1` | Type | `uint8` | `0x03 ^ 0x5A` |
| `2` | `Pid_Id` | `uint8` | 要修改的 PID 编号 |
| `3~6` | `Kp` | `float32` | 新比例参数 |
| `7~10` | `Ki` | `float32` | 新积分参数 |
| `11~14` | `Kd` | `float32` | 新微分参数 |
| `15~16` | CRC16 | `uint16` | CRC 校验值 |

下位机处理要求：

- `Pid_Id` 不存在时返回 `PID_NOT_FOUND`。
- `Kp、Ki、Kd` 中任意值为 `NaN`、正负无穷或超出固件自身安全范围时，返回 `INVALID_PARAMETER`。
- 三个参数必须作为一次原子操作同时生效，不能只更新其中一部分。
- 参数只写入 RAM；协议不包含保存到 Flash 的命令。
- 成功 ACK 必须回传最终实际生效的 float32 值，上位机以 ACK 返回值为准。

## 6. 下位机发送帧

### 6.1 PID 信息帧：`PID_INFO`

用途：返回指定 PID 实例的名称和参数，也用于报告编号不存在。

```text
帧类型：0x81
Payload 长度：48 bytes
总长度：52 bytes
```

| 偏移 | 字段 | 类型 | 说明 |
| ---: | --- | --- | --- |
| `0` | SOF | `uint8` | `0xA5` |
| `1` | Type | `uint8` | `0x81 ^ 0x5A` |
| `2` | Status | `uint8` | `0x00` 成功，`0x01` 不存在 |
| `3` | `Pid_Id` | `uint8` | 被查询的 PID 编号 |
| `4~35` | `Name` | `char[32]` | UTF-8 名称，末尾补 `0` |
| `36~39` | `Kp` | `float32` | 比例参数 |
| `40~43` | `Ki` | `float32` | 积分参数 |
| `44~47` | `Kd` | `float32` | 微分参数 |
| `48~49` | Reserved | `uint16` | 保留，发送 `0` |
| `50~51` | CRC16 | `uint16` | CRC 校验值 |

`PID_INFO.Status` 状态码：

| 值 | 名称 | 说明 |
| ---: | --- | --- |
| `0x00` | `OK` | PID 实例存在，后续字段有效 |
| `0x01` | `NOT_FOUND` | PID 编号不存在，后续字段无效 |

当 `Status = 0x01` 时，仍必须发送完整固定长度帧，并满足：

- `Pid_Id` 原样回显被查询的编号。
- `Name[0..31]` 全部填 `0`。
- `Kp、Ki、Kd` 全部填 `0.0f`。
- `Reserved` 填 `0`。

### 6.2 高频监视帧：`MONITOR`

用途：按照最近一次 `SELECT_CHANNELS` 的配置，周期性发送 4 个通道的目标值和测量反馈值。

```text
帧类型：0x84
Payload 长度：40 bytes
总长度：44 bytes
```

| 偏移 | 字段 | 类型 | 说明 |
| ---: | --- | --- | --- |
| `0` | SOF | `uint8` | `0xA5` |
| `1` | Type | `uint8` | `0x84 ^ 0x5A` |
| `2~5` | `Timestamp` | `uint32` | 当前 RTOS 时间刻，单位为毫秒 |
| `6~14` | Channel 0 | 见下表 | 通道 0 数据 |
| `15~23` | Channel 1 | 见下表 | 通道 1 数据 |
| `24~32` | Channel 2 | 见下表 | 通道 2 数据 |
| `33~41` | Channel 3 | 见下表 | 通道 3 数据 |
| `42~43` | CRC16 | `uint16` | CRC 校验值 |

每个通道占 9 bytes：

| 通道内偏移 | 字段 | 类型 | 说明 |
| ---: | --- | --- | --- |
| `0` | `Pid_Id` | `uint8` | 当前通道对应的 PID 编号，未使用为 `0xFF` |
| `1~4` | `ref` | `float32` | PID 目标值 |
| `5~8` | `measure` | `float32` | PID 测量反馈值 |

即使某个通道未使用，也必须发送完整的 9 bytes；未使用通道的 `ref` 和 `measure` 填 `0.0f`。

MONITOR 生成要求：

- 一个 MONITOR 帧中的 `Timestamp` 和 4 个通道值必须来自同一次逻辑快照，避免字段跨 PID 计算周期撕裂。
- 帧中的 `Pid_Id` 必须与最近一次成功 `SELECT_CHANNELS` 的配置一致。
- `Timestamp` 使用无符号 32 位毫秒计数，允许自然回绕。约每 `49.71` 天回绕一次；两端计算时间差时必须使用无符号减法。
- MONITOR 不要求 ACK，也不重传。单帧损坏或丢失后直接等待下一帧。
- 下位机复位后，在收到成功的 `SELECT_CHANNELS` 之前不得主动发送 MONITOR。

### 6.3 应答帧：`ACK`

用途：报告选择通道或参数调节操作是否成功，并返回当前生效的 PID 参数。

```text
帧类型：0x83
Payload 长度：17 bytes
总长度：21 bytes
```

| 偏移 | 字段 | 类型 | 说明 |
| ---: | --- | --- | --- |
| `0` | SOF | `uint8` | `0xA5` |
| `1` | Type | `uint8` | `0x83 ^ 0x5A` |
| `2` | `Command_Type` | `uint8` | `0x02` 选择通道，`0x03` 调节参数 |
| `3` | `Status` | `uint8` | 见状态码 |
| `4` | `Pid_Id` | `uint8` | 参数操作对象；选择通道时填 `0xFF` |
| `5~8` | `Kp` | `float32` | 当前生效值；无参数操作时填 `0.0f` |
| `9~12` | `Ki` | `float32` | 当前生效值；无参数操作时填 `0.0f` |
| `13~16` | `Kd` | `float32` | 当前生效值；无参数操作时填 `0.0f` |
| `17~18` | Reserved | `uint16` | 保留，发送 `0` |
| `19~20` | CRC16 | `uint16` | CRC 校验值 |

状态码：

| 值 | 名称 | 说明 |
| ---: | --- | --- |
| `0x00` | `OK` | 操作成功 |
| `0x01` | `PID_NOT_FOUND` | PID 编号不存在 |
| `0x02` | `INVALID_PARAMETER` | 参数非法 |
| `0x03` | `INVALID_CHANNEL` | 通道配置非法 |
| `0x04` | `CRC_ERROR` | 保留；当前 CRC 错误帧静默丢弃 |
| `0x05` | `UNSUPPORTED_COMMAND` | 保留；当前未知类型帧静默丢弃 |

ACK 字段填写规则：

| 原命令 | `Command_Type` | `Pid_Id` | `Kp、Ki、Kd` |
| --- | ---: | ---: | --- |
| `SELECT_CHANNELS` | `0x02` | `0xFF` | 全部 `0.0f` |
| `SET_PID` 成功 | `0x03` | 操作对象 | 最终实际生效值 |
| `SET_PID` 失败 | `0x03` | 操作对象 | 当前仍生效的值；若对象不存在则全部 `0.0f` |

`Reserved` 必须填 `0`。一次合法请求只产生一个对应的 PID_INFO 或 ACK。

## 7. 通信行为

### 7.1 请求与响应规则

协议没有序号字段，因此上位机必须遵守以下规则：

- 同一时间最多存在一个等待 PID_INFO 或 ACK 的请求。
- 收到对应响应或等待超时后，才能发送下一个请求。
- MONITOR 是异步周期帧，可以出现在请求与响应之间；上位机必须按帧类型分发，不能把 MONITOR 当作请求响应。
- 当前上位机响应超时为 `800 ms`；`READ_PID` 最多尝试 3 次，`SELECT_CHANNELS` 与 `SET_PID` 失败后由用户决定是否重试。
- 下位机收到合法请求后应尽快响应，不能等待下一个 MONITOR 周期才处理。

### 7.2 获取 PID 实例列表

```text
上位机                         下位机
   │── READ_PID(Pid_Id=0) ──────>│
   │<──────── PID_INFO ──────────│
   │── READ_PID(Pid_Id=1) ──────>│
   │<──────── PID_INFO ──────────│
   │             ...             │
   │── READ_PID(Pid_Id=N) ──────>│
   │<── PID_INFO(PID_NOT_FOUND) ─│
```

上位机收到 `PID_INFO.NOT_FOUND` 后停止遍历。PID 编号必须从 `0` 连续递增；中间缺号会被视为列表结束。

### 7.3 选择监视通道

上位机发送 `SELECT_CHANNELS` 后等待 `ACK`。只有收到 `Status = OK` 后，下位机才使用新的通道配置并发送 `MONITOR` 帧。

当前上位机连接后的初始化顺序为：

1. 从 PID 0 开始执行实例枚举。
2. 取前 4 个 PID 编号，数量不足时以 `0xFF` 补齐。
3. 发送一次 `SELECT_CHANNELS`。
4. 收到 `ACK(OK)` 后进入监视状态。

### 7.4 参数调节

上位机发送 `SET_PID` 后等待 `ACK`。成功后参数立即应用于 PID 计算，但不保存到非易失存储器。下位机在应答中返回最终生效值。

### 7.5 下位机发送调度

建议使用一个统一 TX 队列，由 UART 中断或 DMA 顺序发送完整帧：

1. PID_INFO 和 ACK 属于高优先级响应帧。
2. MONITOR 属于可丢弃的周期帧。
3. 若发送队列拥塞，应优先保留响应帧并丢弃旧 MONITOR，不能阻塞 PID 控制任务。
4. 已经开始发送的帧必须完整发送，不能被高优先级帧插入。

## 8. 带宽估算

`MONITOR` 帧固定为 44 bytes。`115200 bps、8N1` 下理论串口吞吐量约为 `11520 bytes/s`：

```text
11520 / 44 ≈ 261 帧/s
```

考虑串口调度、请求帧和其他系统开销，4 通道监视建议使用 `100~200 Hz`。监视帧不进行重传，丢帧后直接等待下一帧。

| MONITOR 频率 | 数据量 | 占 115200/8N1 理论吞吐 |
| ---: | ---: | ---: |
| 100 Hz | 4400 bytes/s | 约 38.2% |
| 150 Hz | 6600 bytes/s | 约 57.3% |
| 200 Hz | 8800 bytes/s | 约 76.4% |

下位机建议默认使用 `100 Hz`。若使用 `200 Hz`，必须确认响应帧仍能及时进入发送队列，且 UART/DMA、RTOS 调度和上位机处理均有足够余量。

## 9. 协议测试向量

十六进制序列按实际发送顺序排列，最后两个字节均为 CRC 低字节、CRC 高字节。

### 9.1 READ_PID：读取 PID 0

```text
A5 5B 00 4A CF
```

### 9.2 SELECT_CHANNELS：绑定 PID 0、1、2，通道 3 未使用

```text
A5 58 00 01 02 FF B1 49
```

### 9.3 SET_PID：PID 0，Kp=1.0，Ki=0.5，Kd=0.25

```text
A5 59 00 00 00 80 3F 00 00 00 3F 00 00 80 3E 58 F9
```

其中三个 float32 的 Little-Endian 字节分别为：

```text
1.0  = 00 00 80 3F
0.5  = 00 00 00 3F
0.25 = 00 00 80 3E
```

### 9.4 MONITOR 示例

条件：

- `Timestamp = 1000 ms`
- Channel 0：`Pid_Id=0, ref=1.5, measure=2.5`
- Channel 1~3：未使用

```text
A5 DE E8 03 00 00
00 00 00 C0 3F 00 00 20 40
FF 00 00 00 00 00 00 00 00
FF 00 00 00 00 00 00 00 00
FF 00 00 00 00 00 00 00 00
43 CB
```

固件单元测试至少应覆盖：标准 CRC 向量、上述 4 个完整帧、错误 CRC、未知类型、分片接收、连续多帧、Payload 内出现 `0xA5`、接收超时以及时间戳回绕。

## 10. 下位机实现检查表

- 不直接发送 C/C++ 结构体，必须逐字段序列化，避免结构体对齐和编译器差异。
- `Name` 最多存放 31 个 UTF-8 字节，最后 1 字节必须为 `0`；超过长度的名称应在下位机侧截断或拒绝。
- PID 编号必须从 `0` 开始连续递增，不能出现中间缺号；否则上位机遍历会提前结束。
- `Pid_Id = 0xFF` 仅用于表示未使用的监视通道，不能作为有效 PID 编号。
- 参数调节只在 RAM 中生效，设备重启后不保证保留。
- CRC 错误、未知帧类型或接收超时后，接收端丢弃当前帧并重新搜索 `0xA5`。
- RX 状态机必须能处理一次收到半帧、完整一帧或连续多帧的情况。
- UART RX 建议使用环形缓冲区；协议解析不得阻塞 PID 控制任务。
- UART TX 必须使用统一队列保证帧不交错；队列拥塞时允许丢弃 MONITOR，不得丢弃已生成的 ACK/PID_INFO。
- 通道配置和 PID 参数更新必须原子生效。
- 发送前写零所有 Reserved 与未使用通道数据。
- 使用第 9 节测试向量与上位机进行联调后，再提高 MONITOR 频率。
